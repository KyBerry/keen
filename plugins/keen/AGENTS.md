# Keen contributor guide

This directory is the source of truth for the local Keen plugin. Do not
edit the versioned copy under `~/.claude/plugins/cache`; Claude owns that cache.

## Product boundary

The Python CLI measures rendered UI and writes deterministic artifacts. Agent
instructions interpret those artifacts. Keep measurement rules in Python and
judgment/output guidance in the skill.

## Agent surface

- `skills/keen/SKILL.md` is the canonical Claude/Codex router and safety contract.
- `skills/ui-*/SKILL.md` are direct, cross-platform operational workflows.
- `skills/keen/references/` contains optional guides loaded only for the
  active mode.
- `skills/*/agents/openai.yaml` contains Codex presentation and invocation policy.
- `.claude-plugin/plugin.json` and `.codex-plugin/plugin.json` are both release surfaces.
- `../../codex-plugins/keen/` is generated by
  `scripts/sync_codex_plugin_bundle.py`; never edit the bundle by hand.
- `README.md` documents the truthful local install and update process.

When changing commands or skills:

1. Keep trigger descriptions specific enough to distinguish neighboring modes.
   The umbrella skill may activate implicitly; focused Codex skills may not.
2. Never interpolate the host's aggregate command-argument variable in a Bash
   snippet. Treat user input as data, allowlist options from CLI help, construct
   argv, and quote dynamic values.
3. Use the canonical `keen` executable in user-facing docs and scripts.
4. Do not install dependencies as a side effect of a review command.
5. Do not write user systems or output into `${CLAUDE_PLUGIN_ROOT}`.
6. Use exact system identifiers accepted by the CLI (`apple-hig`, `fluent-2`,
   `material-3`, `polaris`, `carbon`, `atlassian`).
7. Keep loose-image instructions independent of `report.json`.
8. Do not grant `Write` in shared skill frontmatter. Creation workflows must
   keep output in a user-owned project directory and let the host enforce tool
   approval.
9. Add or update activation cases whenever a skill trigger or boundary changes.

## Verification

From this plugin directory, run:

```bash
python3 scripts/validate_prompts.py
python3 scripts/evaluate_skill_contracts.py
python3 scripts/sync_codex_plugin_bundle.py --check
python3 -m pytest -q
ruff check harness tests
mypy harness
python3 /Users/kyleberry/.codex/skills/.system/plugin-creator/scripts/validate_plugin.py .
claude plugin validate ../..
claude plugin validate .
```

Also inspect the context budget with:

```bash
claude plugin details keen@keen
```

For release work, verify every version surface agrees and test a clean built
package; an editable development install is not proof that packaged resources
work.
