# UI Systemize

Read `../keen/SKILL.md` first, then `../keen/references/system-design.md`.

Require one run directory. Accept only options from `keen systemize --help` and safely quote every dynamic value. Review the generated JSON, Markdown, and preview as a proposal: choose an archetype, prune scales, clarify semantic roles and component rules, validate, and re-render when needed.

Recapture the absolute preview HTML at mobile and desktop widths with `--allow-file`, inspect both rendered PNGs, and run `keen slop` on that verification run. Preserve captured product copy and typography evidence; label synthetic stress copy. Reject numbered chapter theater, report-chrome display fonts, decorative status metadata, generic slogans, fake product specimens, and card-per-section composition unless product evidence requires them. Fix document structure rather than adding ornamental variety.

Keep output under the user's project. Never write a system into the plugin source or either platform's plugin cache. Do not claim the new name works with `--against` unless a supported install command exists and readback proves registration.
