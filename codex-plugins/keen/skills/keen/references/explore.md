# Explore guide

Use exploration to make a choice, not to assemble a collage of fashionable UI.

Start with the audience, product job, content, and emotional target. If the
user supplied references, inspect those first. If research is requested, gather
a small varied set of current primary examples and retain source links. Label
what each reference contributes and what must not be copied.

Offer two or three genuinely different directions. Each direction should name:

- a concrete visual and emotional thesis;
- composition and information-hierarchy behavior;
- display/body typography roles with pairing rationale;
- color, density, shape, imagery, icon, and motion tendencies;
- one product-specific interaction or content idea;
- likely failure modes and implementation cost.

Do not vary only accent color, radius, or font. Do not invent fake brand
evidence, testimonials, metrics, or product features to make a direction look
complete.

For a moodboard, organize references by the decision they inform rather than
by decorative theme. Capture `source`, `take`, `avoid`, and `notes` in the
project design context. The user should be able to reject one influence while
keeping another.

Do not fetch images merely to make exploration look substantial. Product copy,
layout, typography, density, action hierarchy, icon behavior, and motion can be
tested as live specimens in a local workshop. Use external references only
when they contribute evidence the codebase and a small prototype cannot.

End with a choice the user or agent can make: preferred direction, useful
hybrid, unresolved decision, and the smallest prototype that would test it.
